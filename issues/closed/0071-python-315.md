# Python 3.15 / 3.15t への対応

- Created: 2026-11-07
- Completed: 2026-11-08
- Branch: feature/python-315
- Polished:

## 目的

Python 3.15 と free-threading ビルド (3.15t) でも moqt-py の PyO3 拡張をビルドし、
テストが通るようにする。3.14 / 3.14t の対応は維持する。

## 現状

- `pyproject.toml` の `requires-python` は `>=3.14`、classifier は 3.14 のみだった
- `.python-version` は 3.14 で、CI の pytest も 3.14 だけで実行していた
- PyO3 0.29.2 は Python 3.15 に対応しており、`#[pymodule(gil_used = false)]` も
  指定済みだったため、Rust 側の変更は不要だった
- `uv.lock` の `cryptography` 50.0.0 には free-threaded 3.15 向けの wheel が無く、
  3.15t ではソースビルドになり OpenSSL の開発ヘッダーを要求して失敗した
  (`cryptography` 50.0.2 には `cp315-abi3.abi3t` の wheel がある)

## 設計方針

- `requires-python` は `>=3.14` のままにし、3.14 系と 3.15 系の両方をサポートする
- `.python-version` は 3.14 のままにし、CI で 3.15 / 3.15t のジョブを追加する
- free-threaded 3.15t のテストに必要な `cryptography` を 50.0.2 へ更新する
- ローカルで 3.15 系を試すときは `UV_PROJECT_ENVIRONMENT` で Python ごとの venv を作る
- `.venv-*/` を `.gitignore` に追加し、CI とローカルの検証用 venv を追跡しないようにする

## 解決方法

- `pyproject.toml`
  - `Programming Language :: Python :: 3.15` を追加した
- `uv.lock`
  - `cryptography` を 50.0.0 から 50.0.2 へ更新した。50.0.2 は
    `cp315-abi3.abi3t` の wheel を持つため、3.15t でもソースビルドにならない
- `.github/workflows/ci.yml`
  - `python-315` ジョブを追加し、`3.15` と `3.15t` の matrix で
    `uv sync` と `pytest` を実行する
  - runner は既存の Rust 拡張ビルドと同じ `ubuntu-26.04` を使う
  - CI のコメントに残っていた webtransport-py 前提の runner の説明を現在の構成へ直した
- `README.md` / `skills/moqt-py/SKILL.md` / `docs/DEVELOPMENT.md`
  - 対応 Python に 3.15 / 3.15t を追加した
  - ローカルで 3.15 / 3.15t を検証するコマンドを DEVELOPMENT に追加した
- `.gitignore`
  - `.venv-*/` を追加した

実装とテストは完了し、develop へコミット済みである。
